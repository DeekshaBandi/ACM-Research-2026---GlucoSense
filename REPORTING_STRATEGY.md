Canonical reference for co-authors. This document is the **single source

primary, and which branch produces which result. If the code and this

## 1. Decisions

| Item | Decision |
|---|---|
| **Primary endpoint** | `label_median` (daily CV ≥ cohort median). Pre-declared primary endpoint for the harmonized analysis; balanced and the most methodologically defensible for this normoglycemic feasibility cohort. |
| **Main pipeline (branch)** | `harmonized-primary-analysis` |
| **Main models** | Co-primary: Random Forest + XGBoost. Logistic Regression is a full-feature baseline only (see `train_baseline.py`). |
| **Chance floor** | `DummyClassifier(strategy="stratified")` run on every subset. |
| **Validation** | Leave-One-Subject-Out CV (16 participants). Fold-SE 95% CI on per-fold AUROC mean. Participant-stratified cluster bootstrap for pooled AUROC CI. |
| **Ranking policy** | No single "winner." Report the top-tier CI-overlap cluster (`T` flag in `ablation.py`) as candidate minimal configurations. |
| **MAGE sensitivity** | `label_mage_median` — pre-specified robustness probe only. Reported in one table. MUST NOT re-rank subsets. |
| **p75 sensitivity** | `label_p75` — pre-specified robustness probe only. Reported in one table. MUST NOT re-rank subsets. |
| **`deeksha` branch role** | Appendix / robustness source only. Supplies the label-dependence discussion and the participant-cluster bootstrap methodology. NOT a main-results branch. |
| **Other ablation branches** | `laasya-sensor-ablation`, `stage3-sensor-ablation-de`, `laasya_rfimplementation` — comparison/diagnostic only. Do not merge their logic unless a specific fix is explicitly identified and approved. |

## 2. Paper structure

### Main Results
- One endpoint (`PRIMARY_ENDPOINT == label_median`), one pipeline, one ablation table.
- Produced by `ablation.py` on `harmonized-primary-analysis`.
- Report: fold-mean AUROC ± std, fold-SE 95% CI, `auroc_folds_eval`, for RF + XGB + Dummy.
- Describe the top-tier CI-overlap cluster; do **not** name a single winner.

### Sensitivity Analysis
Two subsections, both generated by `sensitivity_and_report.py`:
1. **MAGE re-run** (`label_mage_median`). One table. State whether the primary top-tier cluster holds.
2. **CV-p75 re-run** (`label_p75`). One table. Flag near-chance behavior and degenerate folds honestly.

Neither may be used to re-rank subsets or re-declare a candidate minimum.

### Appendix / Robustness
Sourced from the `deeksha` branch:
- Label-dependence finding: the ranking of minimal subsets depends on the variability endpoint (ACC-family advantage from CV labeling inverts under MAGE labeling).
- Participant-stratified cluster bootstrap methodology.
- Per-fold AUROC variance and degenerate-fold counts.

## 3. Draft paragraphs (approved, conservative)

**Main results.** In a 16-participant feasibility cohort, we evaluated 17 sensor subsets under LOSO-CV against a pre-registered primary label (daily CV ≥ cohort median). Random Forest and XGBoost were co-primary; a stratified Dummy classifier provided a chance floor. Across subsets, per-fold AUROC overlapped substantially, and a top-tier cluster of subsets was statistically indistinguishable from the leader under fold-SE 95% confidence intervals. We therefore report a candidate set of minimal wearable configurations rather than a single winner, and note which subsets cleanly exceeded the Dummy floor.

**Sensitivity analysis.** We repeated the full ablation under two pre-specified alternative labels: a cohort-median split on MAGE and a CV 75th-percentile split. The MAGE re-run reordered several minimal subsets relative to the primary CV-median analysis, and the p75 re-run showed performance compressed toward chance, consistent with the reduced positive class and increased fold degeneracy. We interpret these shifts as evidence that subset rankings are label-dependent in this cohort rather than as contradictory findings.

**Limitations.** This is a 16-participant feasibility study with cohort-relative labels; thresholds are not clinical (the AACE CV ≥ 36% cutoff is shown only as a reference column) and findings should not be read as clinical classification of glycemic instability. LOSO folds were frequently degenerate (single-class held-out subjects), inflating per-fold variance. Participant-cluster bootstrap 95% CIs overlap heavily across subsets, so we avoid "best sensor" language. Results are specific to this cohort, pipeline, and label definition and require replication in a larger, clinically labeled dataset before any minimum-sensor claim can be generalized.

## 4. How to reproduce the main-paper numbers

From the repo root on `harmonized-primary-analysis`:

```bash
python3 train_baseline.py        # full-feature baseline (LR + RF + XGB)
python3 ablation.py              # main ablation: RF + XGB + Dummy x 17 subsets
python3 sensitivity_and_report.py  # sensitivity + final interpretation block
```

Key outputs consumed by the paper:
- `results/baseline_metrics.csv` — full-feature baseline table
- `results/ablation_metrics_rf.csv`, `results/ablation_metrics_xgb.csv`, `results/ablation_metrics_dummy.csv` — main-paper ablation
- `results/final_ablation_comparison.csv` — RF vs XGB side-by-side, mean-rank sorted
- `results/sensitivity_metrics_p75.csv`, `results/sensitivity_metrics_mage.csv` — the two pre-specified sensitivity tables
- `results/final_config.json` — machine-readable summary with `primary_endpoint` + both sensitivity labels
- `results/model_selection.json` — co-primary rationale + candidate minimal config

## 5. What NOT to do

- Do **not** present p75 or MAGE as an alternate primary endpoint.
- Do **not** name a single "best sensor" or "winner" in the main text.
- Do **not** compare against the clinical CV ≥ 36% threshold as if this cohort populates it — the cohort is normoglycemic.
- Do **not** port logic from `laasya-sensor-ablation`, `stage3-sensor-ablation-de`, or `laasya_rfimplementation` into this branch without an explicit, named change request.
- Do **not** generalize the minimum-sensor finding beyond this cohort, pipeline, and label definition.
